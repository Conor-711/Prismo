# bSmart iOS UI 竞品调研：Fomo 与 Hyperdash

> 状态：Signal Pulse 第一批已实现
> 日期：2026-08-05
> 适用范围：iOS 设计系统、Today、事件详情、Smart、Research、Portfolio
> 产品范围真源：`docs/product/product-direction-mvp.md`

## 1. 研究目标

bSmart 不应被改造成交易终端或社交 Feed。本次研究只回答一个问题：如何让持仓事件、Smart Account
和 Smart Money 在 iPhone 上更容易理解和操作，同时保留可审计的专业证据。

研究对象分工：

- **Fomo**：移动优先的信息层级、年轻化视觉、社交行为流和短操作路径。
- **Hyperdash**：专业证据结构、交易者分组、仓位变化、排行榜和模块联动。

结论不是二选一，而是：

> **表层体验学习 Fomo，证据结构学习 Hyperdash。**

## 2. Fomo：值得采用的模式

### 2.1 每屏只有一个主要任务

Fomo 的买入、排行榜、资产发现和社交行为流都围绕单一任务组织。页面不会先解释产品功能，再要求用户
寻找入口。主要数字、主要对象和主要动作在第一屏内形成完整闭环。

对 bSmart 的含义：

- Today 首屏回答“今天最需要关注什么”，不展示泛化市场信息；
- 事件详情首屏回答“发生了什么、和我有什么关系”，不先铺满指标；
- Smart Account 详情首屏回答“这个人最近说了什么、为什么值得看”；
- Smart Money 详情首屏回答“这个公开账户刚刚做了什么、规模如何”。

### 2.2 用真实对象承载信息

Fomo 的核心列表持续展示头像、用户名、资产 Logo、动作、金额、时间和结果，而不是使用抽象的功能卡片。
这使高密度金融信息仍然具有社交可读性。

bSmart 应更多使用：

- Smart Account 真实头像和平台身份；
- 股票 Logo 与 ticker；
- Smart Money 地址别名和公开账户标识；
- 明确动作动词，例如“首次覆盖”“转为看多”“增加多仓”“减少风险”；
- 原始证据时间，而不只显示算法标签。

### 2.3 Feed 是行为流，不是文章流

Fomo 的 Feed 一行先说明“谁做了什么”，随后用紧凑资产模块承载金额、回报或小型趋势图。用户可以先
扫描行为，再决定是否展开详情。

bSmart Today 应采用同一阅读顺序：

1. 谁或哪类资金发生变化；
2. 涉及哪只持仓；
3. 变化方向和规模；
4. 对用户成本与仓位的影响；
5. 是否存在另一类证据确认；
6. 展开后再看完整解释和原始证据。

### 2.4 排行榜可快速比较

Fomo 的排行榜把名次、头像、名称、时间窗口、绝对/相对收益放在一屏内，并突出前三名。筛选项数量少，
但每个筛选都直接影响用户判断。

bSmart Smart Account 榜单应优先展示：

- Score 与平台内排名；
- 最擅长的赛道和周期；
- 最近观点变化；
- 已结算样本量；
- 关注状态。

筛选保留平台、周期、赛道、风格和排名区间，但默认界面只展示当前生效条件，次要条件进入底部 Sheet。

### 2.5 通知只表达一个变化

Fomo 的通知文案结构非常短：资产变化、多少名头部交易者行动、涉及金额。它先给可验证事实，不在通知中
塞入完整分析。

bSmart 通知建议固定为：

> `NVDA · 3 位高分作者转为谨慎`
> `你的 NVDA 仓位为 18%；链上资金暂未同步减仓。`

通知点击后进入事件详情，完整解释留在 App 内。

### 2.6 不应照搬的部分

- 不复制 Fomo 的紧迫感、游戏化交易和一键买入路径；
- 不使用收益金额替代 Smart Account 的证据质量；
- 不用大面积紫蓝背景覆盖 bSmart 的品牌色；
- 不把用户引向无限社交 Feed；
- 不在切换到动作页时隐藏关键上下文。

App Store 反馈中已经出现 PnL 准确性、存取款清晰度、榜单风格不匹配，以及进入交易流程后看不到图表等
问题。bSmart 的 UI 必须把数据时间、样本量、计算口径和原始证据视为信任基础。

## 3. Hyperdash：值得采用的模式

### 3.1 按任务组织模块，而不是堆满所有指标

Hyperdash 支持按交易、资金流和持仓复盘保存不同布局。同一模块可以最大化，也可以与其他模块联动。

bSmart 不需要让用户自由拖拽，但应预设三种明确上下文：

- **Today**：按用户持仓排序的事件；
- **Research**：围绕当前 ticker 联动的证据模块；
- **Smart**：围绕当前投资者或公开账户联动的历史与最新变化。

### 3.2 模块之间共享同一个对象

Hyperdash 的图表、订单簿、Top Traders 和 Position Changes 可以跟随同一资产。bSmart 应使用同样的
上下文联动原则：进入 NVDA 后，页面内所有 Smart Account、Smart Money、价格上下文和事件都只能解释
NVDA，不能出现需要用户反复选择 ticker 的重复筛选器。

### 3.3 专业数据要能逐层展开

Hyperdash 的 Top Traders、Cohorts 和 Position Changes 分别回答：谁的仓位最大、不同群体如何定位、
最近谁改变了仓位。三者不是同一张多空图的重复表达。

bSmart Smart Money 的移动端结构应为：

1. 当前方向变化；
2. 发生变化的高分公开账户；
3. 多空账户数与名义规模；
4. 变化前、变化量、变化后；
5. 数据覆盖、流动性与限制。

### 3.4 排名必须包含风格和时间窗口

Hyperdash 的榜单同时支持市场、时间窗口、账户规模、胜率和交易风格。bSmart 现有的平台、周期、赛道、
风格和排名区间方向正确，但需要从横向按钮堆叠改为“摘要筛选条 + 底部筛选 Sheet”。

### 3.5 提醒与实时追踪是不同场景

Hyperdash 将平台 Inbox 与已追踪钱包的实时活动流分开。bSmart 也应区分：

- **提醒**：达到事件门槛、与用户持仓相关、需要主动送达；
- **追踪流**：用户主动关注的 Smart Account 或 Smart Money 最新变化；
- **系统消息**：数据延迟、覆盖变化和产品通知。

不能把所有变化都推送，也不能把未达到门槛的追踪动态包装成持仓事件。

### 3.6 不应照搬的部分

- 不复制桌面终端的多栏网格和常驻表格；
- 不在 iPhone 上展示订单簿级信息密度；
- 不开放自由布局编辑器；
- 不把交易执行入口混入第一阶段；
- 不为了“专业感”同时显示所有可计算指标。

## 4. bSmart 当前 UI 诊断

当前 iOS 已具备 Today、Smart、Portfolio、Research 和事件详情闭环，深色基础、真实头像、股票 Logo、
状态色和固定底部导航也与目标方向一致。主要问题是：

1. **卡片权重过于平均**：组合摘要、日报、筛选器和事件都被边框包围，用户难以识别主任务；
2. **Today 顶部过高**：持仓市值占据大量首屏空间，真正的事件被推到下方；
3. **事件卡更像研究摘要**：标题与长摘要优先，人物动作、变化量和证据关系不够突出；
4. **筛选器占据视觉注意力**：横向滚动项多，但多数不是高频操作；
5. **Smart 列表仍像设置页 List**：缺少榜单的比较节奏和头部作者视觉信号；
6. **详情页模块化不足**：已有数据完整，但“结论—证据—限制—下一步”的阅读层级仍可强化；
7. **中英文动态内容不统一**：UI 已本地化，但原始证据、产品生成内容和固定术语的语言边界需要明确。

## 5. 目标设计方向

### 5.1 视觉原则

- 保留近黑背景、白色主文本和 bSmart 青绿色；
- 使用克制的荧光绿色作为 Pulse 交互色，红色只用于明确风险，金色只用于待确认；
- 减少外层卡片和重复边框，用间距、分隔线和局部浅色面建立层级；
- 圆角不超过 8pt；
- 数字使用等宽数字，关键变化使用大号数字，解释保持普通字号；
- 真实头像和资产 Logo 是第一视觉锚点；
- 避免渐变背景、装饰光球和无信息价值的发光效果；
- 动效只用于状态变化、展开和上下文切换，默认 160–240ms，并支持 Reduce Motion；
- 主要交互使用轻触觉反馈，风险状态不使用娱乐化庆祝动画。

### 5.2 信息原则

- 一屏一个主要问题；
- 先变化，后解释；
- 先用户关系，后全市场事实；
- 先结论和两类证据关系，后指标细节；
- 每个数字必须带时间窗口、对象或口径；
- 原始证据永远可达，AI 解释不能替代证据；
- 无 Smart Money 数据时明确显示“暂无资金验证”，不能用中性样式掩盖缺失。

## 6. 页面改版映射

### P0：Today

- 将大号持仓市值卡压缩为一行组合状态条；
- 首屏直接展示“最需要关注”的一条事件；
- 事件行改为“主体动作 + ticker 证据模块 + 用户影响”；
- 将全部筛选收敛为 `全部 / 风险 / 机会 / 未读`，其他条件放入 Sheet；
- 日报使用轻量入口，不与首要事件竞争；
- 机会发现放在持仓事件之后，并明确“未持有”。

### P0：事件详情

- 顶部显示 ticker、发生时间、优先级和与持仓关系；
- 第一模块只展示一句结论与变化前后；
- 第二模块并列展示 Smart Account 与 Smart Money 状态；
- 第三模块展示原始证据时间线；
- 最后展示反方证据、数据限制和下一步研究；
- 保存、忽略和反馈放在底部操作栏，不挤占结论区。

### P0：Smart

- Smart Account 与 Smart Money 继续保持平行入口；
- Account 榜单采用头像、名次、Score、专长、周期和最近变化的紧凑行；
- Money 榜单采用公开账户、方向变化、规模、活跃 ticker 和数据时间的紧凑行；
- 筛选改为单一摘要条，点击后打开统一底部 Sheet；
- 详情页突出最新已验证动作，历史指标降到下一层。

### P1：Research

- 搜索进入 ticker 后，固定资产头部只保留价格上下文、持仓关系和当前结论；
- 预设 `概览 / Smart Account / Smart Money` 三个视图；
- 所有模块自动跟随当前 ticker，不重复放置 ticker 筛选；
- 使用小型变化图，不恢复 Web 的完整交易终端。

### P1：Portfolio

- 使用紧凑持仓列表，突出仓位占比、成本关系和未读事件数；
- 组合总值只作为摘要，不占据主要内容高度；
- 观察列表与真实持仓视觉上明确区分；
- 添加/编辑持仓使用半屏 Sheet 和即时预览。

### P2：设置与状态页

- 统一底部 Sheet、空状态、Skeleton、错误状态和延迟状态；
- 设置页保持原生 iOS 结构，不强行套用 Fomo 风格；
- 数据来源、方法和风险披露继续以可读性优先。

## 7. 开发顺序与验收

### 第一批：设计系统与 Today

1. 更新颜色角色、字体角色、间距和动效 token；
2. 新增紧凑资产行为行、证据关系条、筛选 Sheet、组合状态条；
3. 重构 Today 首屏和事件卡；
4. 保持现有模型、排序、事件逻辑和导航不变；
5. 在中文和英文、常见 iPhone 尺寸、Dynamic Type 下截图验收。

### 第二批：事件详情与 Smart

1. 重构事件详情阅读顺序；
2. 重构 Smart Account / Smart Money 榜单；
3. 统一作者和公开账户详情的最新动作模块；
4. 补充筛选叠加和可访问性测试。

### 第三批：Research 与 Portfolio

1. 建立 ticker 联动的精简研究页；
2. 压缩持仓摘要，强化事件入口；
3. 统一空数据、延迟和单证据覆盖状态；
4. 完成全流程性能和视觉回归。

验收标准：

- 用户打开 Today 后 3 秒内能指出最重要事件；
- 首屏无需滚动即可看见至少一条完整的持仓事件；
- 每条事件能在不展开时识别主体、ticker、方向、时间、用户关系和证据覆盖；
- 进入详情后两次点击内可以到达原始证据；
- Smart 榜单无需横向滚动即可比较主要指标；
- 页面没有因为追求年轻化而降低数据时间、样本量和限制说明的可见性；
- 现有业务测试、契约测试和核心 UI 流程继续通过。

## 8. Signal Pulse 第一批实现记录

2026-08-11 已完成方案 1 的首轮原生 SwiftUI 落地：

- 设计系统新增页面标题、圆形图标按钮、紧凑指标条、轻量分区标题和并列证据状态组件；
- Today 首屏改为持仓监测标题、三项状态条、一条最高优先级事件和轻量日报入口；
- 事件详情强化结论边线，并把 Smart Account / Smart Money 当前证据并列展示；
- Smart 榜单保留现有完整叠加筛选逻辑，但默认只展示一个筛选入口，具体条件进入系统 Sheet；
- Portfolio 使用紧凑摘要与持仓行；无价格的仓位比例场景只展示真实仓位信息，不伪造零市值；
- Research 列表改为紧凑 intelligence 行，标的详情增加 `概览 / Smart Account / Smart Money` 上下文切换；
- 底部 Tab 与主要选中态统一使用 Pulse 色，Today 徽标只显示未读持仓事件数；
- 中英文与 VoiceOver 名称保持稳定，视觉大写不改变可访问性语义。

模拟器验收基于 iPhone 16，截图保存在 `output/ios-ui/`。后续页面应先复用
`Core/DesignSystem` 的现有原语，再判断是否需要新增共享组件。
