# 新版 Onboarding 方案

> 本方案已由 [发现 → 追踪 → 交易三页方案](onboarding-three-step.md) 取代。以下保留为历史讨论，不作为当前实施依据。

日期：2026-09-16。状态：产品方案，待确认；本轮不修改旧 Onboarding 实现。

## 目标

新用户离开引导时知道三件事：为什么这个人值得关注、如何查看他的投资判断、在哪里继续追踪。最好完成一次自主追踪，而不是记住模块名称或被迫连接券商。

当前实际产品入口是今日、持仓、搜索、交易动态；首页先发现投资者，下半部分是持仓与追踪、市场情况、聪明动态。方案按这个结构设计，不重新宣讲已移除的 AI Tab，不把旧 HTML 当成当前产品。

## 旧版需要解决的问题

- 固定“145 条已结算观点 / 2 个基准 / Live”等说明与当前展示作者不绑定，用户很难理解，也不能作为真实样本规模。
- 第 2 页像功能目录，多个例子的人物、标的不同，缺少连续体验。
- 第 3 页要求已连接券商且至少追踪一人；跳过仅跳到该页，仍不能真正跳过。
- 券商展示流程不应被包装成已验证的真实只读接入，更不应成为浏览研究内容的门槛。
- 旧引导未清晰区分研究判断、Smart Money 实际行为、其他用户的已验证交易。

## 三页结构

### 1. 投资，该追踪谁？

**用户问题：这群人是谁，为什么值得看？**

首屏上半部是 X / YouTube / Reddit 的真实头像池，短暂向一个作者聚焦；下半部直接使用首页的紧凑代表作卡，而非单独画一个抽象评分仪表盘。

- 作者头像、姓名、平台、真实 Top 排名置于同一层级。
- 图上显示最早的至多三个看多节点、各节点价格/日期、后续最高价；右上显示区间最高涨幅。
- 一句自然语言：`作者多次看多 MU，从 $X 到后来最高 $Y。` X/Y、方向和次数全部从经过核对的实际案例生成，没有对应数据就不用这个案例。
- 发布观点只能称“看多”，不能称“买入”。后续区间最高涨幅不是作者实际收益，也不是跟随者可实现收益；图表保留区间，明示历史表现不代表未来收益。
- 排名解释用一句可直接理解的正文：`Top 5%：在本平台参与排名的投资者中，排在前 5%。` 百分比随作者变化；不是收益率、不是胜率。
- 用三个简短节点呈现原理：`公开观点 → 后续表现 → 排名`。更完整的样本/风格/排名信息继续放在已有“对排名有疑问？”页面。
- 背景抓取总人数与正式排名池人数分开取数；不要拿 1000+ 抓取数作为 Top 百分比的分母，不夸大为“全市场前 5%”。

可点图表节点查看原文；默认不强制用户操作。主按钮：**看看他们的判断**。右上：**跳过**，直接进入首页，不进入另一个必填关卡。

### 2. 看懂判断，再决定是否行动

**用户问题：关注之后，bSmart 能为我提供什么？**

沿用第一页的标的/作者，展开一份经过核对的观点，形成连续故事。主视觉是一张可交互的观点详情摘要：作者、方向、理由、价格节点、资料来源。点资料打开对应佐证，没有资料的观点不显示空模块。

下方用两个短例子表达当前实际功能，而非堆术语：

| 当前模块 | 显示方式 | 用户获得的信息 |
| --- | --- | --- |
| 热门标的（原“聪明共识”） | 同一股票旁展示最多三个高排名作者及各自一句理由 | 谁在关注这只股票，理由是否相同；不把“关注同一标的”自动当成共识 |
| 阿尔法标的 | 单个高排名来源及首次/新增覆盖的实际记录 | 哪个值得关注的人提出了较少来源覆盖的新判断；不暗示必然更早或必赚 |

无对应真实聚合时，不为统一故事硬拼出“4 人共识”；使用另一份有来源的实例并明确其标的。

Smart Account 的观点与 Smart Money 的交易行为使用各自的身份/动作标签，不合成为“言行一致”或“背离”信号。已验证的 App 用户交易只在交易动态入口中按实际来源说明，不与研究作者混为一谈。

保留观点详情的交易入口，在教学页只展示与真实页面一致的入口和可取消预览，不真实下单，不生成订单，不触发钱包签名。入金、杠杆、订单风险及确认留到用户实际交易时再介绍。

主按钮：**选几个值得追踪的人**。

### 3. 把值得关注的人留在首页

**用户问题：下次打开，我能看到什么？**

主内容是一组真实的投资者选择行，而不是券商表单。首屏显示三位，再通过“换一批 / 查看更多”浏览。覆盖 X / YouTube / Reddit，也可选择 Smart Money，但不强迫每个平台各选一人。

- 每行包含头像、名称、平台、排名、擅长领域和一句真实代表作/行为；让用户有选择依据，而不只看头像。
- “追踪”是明确的自主操作，不默认替用户关注；点击后的选择写入现有追踪状态，退出引导不丢失。
- 提供少量可选标的，用户可自选关心的股票。连接券商作为次级入口，仅在真实接入可用时展示；不要求入金或钱包才能完成。
- 页面实时显示 `已追踪 N 位`。有选择时主按钮 **进入我的首页**；未选择也可 **先逛逛**。
- 有追踪时首页落在“持仓与追踪”，带出所选作者的最近记录；没有追踪/持仓时落在“市场情况”，不让用户先看到空列表。

首次主动追踪之后再提出通知邀请，可选“开启数据更新通知 / 稍后”。当前实现保证的是发布批次的数据更新通知，不宣称对每位作者都有实时逐条推送。只有用户选择开启时请求 OS 授权；拒绝后不反复弹。

## 节奏与呈现

- 三页各自只有一个主视觉与一个主要操作；预计 30–45 秒完成，但不设置强制等待。
- 复用当前首页的作者、代表作、观点详情组件与浅/深色设计，不再造一套大字营销卡片。
- 同一作者/标的在页面间通过共享元素过渡延续。头像池只做一次短动效，不自动轮播、不滚动抢走阅读位置；遵循 Reduce Motion。
- 标题简短、解释靠实例；排名含义和必要风险说明是正文或就近口径，不是满页功能说明小字。
- 标准屏充分利用空间，紧凑屏和大字号允许滚动，不压缩成小字、不与底部按钮重叠。
- 引导使用审定案例的本地缓存，保留数据日期；更新失败保留最后可用内容，不伪装为实时。

## 功能与发布边界

- 登录/首次资料设置保持现有账户安全流程；引导不更改权限、排名算法、通知投递或交易执行。
- 将“完成引导”与 `hasCompletedPortfolioSetup` 解耦。已有完成记录的用户不强制重看，新版说明可从设置打开。
- 去掉连接券商和追踪数量的硬性完成条件。跳过所有页都能正常使用首页，选择可在以后补全。
- 默认只讲当前能用的能力。Apple 登录尚未配置、通知尚未上线、券商接入仍为原型时，不用引导暗示这些已可用。
- 埋点仅记录页面到达、跳过、查看案例、首次追踪、完成、通知授权结果；不记录原文或资产金额。
- 验收关注首次追踪率、进入首页后打开观点的比例、次日回访，而不是单独追求“三页看完率”。

设计依据：[Apple Onboarding 指南](https://developer.apple.com/design/human-interface-guidelines/onboarding)。采用短、可跳过、可交互的体验，把详细说明放到需要时；以上三页内容为针对 bSmart 当前结构的设计建议，不是 Apple 的指定流程。
